# 日志规范

> 技术栈：C# 5 / .NET Framework 4.x / Windows Forms；无日志框架，使用界面日志区与控制台输出。
> 更新时间：2026-11-19

## 日志渠道

| 渠道 | 触发场景 | 输出位置 |
|------|---------|---------|
| GUI 日志区 | 图形界面操作 | `MainForm` 底部 `RichTextBox`，仅本次会话可见 |
| 控制台 stdout | 命令行模式 | 父控制台（无控制台窗口时 `AttachConsole(-1)` 挂接） |
| 完成弹窗 | 生成结束 | 页数、文件大小、是否打开的询问 |
| 提示音 | 命令行完成 | `user32.dll MessageBeep` |

本项目**不写日志文件、不接入日志框架、无日志级别与保留策略**。如需引入日志框架，应在 Spec 中说明依赖、
级别、输出位置与脱敏方式。

## 输出格式

- GUI 日志：逐图一行结果，如 `<文件名>  →  1 页（上下两片）`、`跳过 <文件名>（<异常消息>）`。
- CLI stdout 固定结构：

```text
PaperToWord v1.3（命令行模式）
输出: <最终 docx 绝对路径>
页数: N            # 或 页数: N，跳过 M 张失败图片
失败: <异常消息>    # 失败时
```

## 反馈与失败处理

- 单图失败写入失败明细并继续处理后续图片；成功页数为 0 时才判定整批失败。
- 失败信息面向本机用户，应包含文件名或异常消息，便于定位。
- **现状提醒**：部分非关键路径（图标加载、EXIF 修正、视觉样式设置、日志追加）使用空 `catch` 吞掉异常
  （来源：`docs/knowledge/architecture.md` 3.1）。这不是通用最佳实践；后续改动该区域时应评估是否需要
  记录，并在 Spec 中说明保留空 `catch` 的理由。
- 失败退出码：命令行模式捕获异常时 `Environment.ExitCode = 1`。

## 敏感信息

- 日志中不得输出图片内容、用户目录以外的隐私信息、凭据或 Token。
- 当前日志只包含本地文件路径、页数、失败原因，无敏感数据。

## 追踪

- 无分布式追踪、无 TraceId（单机单进程工具）。
- 后台线程与 UI 线程通过 `Control.BeginInvoke` 回主线程，日志追加必须发生在 UI 线程。

## 验证

- 手工验证：正常生成、部分图片失败、全部失败、命令行含空格路径、输出目录不存在。
